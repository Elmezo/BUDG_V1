================================================================================
TECHNICAL DETAILS
================================================================================

Backend Implementation:
----------------------
- FuzzySearchUtil generates 3-5 SQL LIKE patterns per search term
- Patterns include:
  * Original query with wildcards
  * Phonetically normalized version
  * Character transposition variants
  * Single-character wildcard substitution
- SQL conditions use OR clauses: (col LIKE ? OR col LIKE ? OR ...)
- Parameters are added for each pattern
- Works with both legacy and AST-based query parsing

Frontend Implementation:
-----------------------
- Multi-strategy matching:
  1. Exact/substring match (fast path)
  2. Wildcard pattern matching
  3. Phonetic normalization
  4. Character transposition checking
  5. Levenshtein distance calculation
- Threshold of 2 character differences (configurable)
- Efficient algorithm optimizations
- Unicode normalization for multi-language support

================================================================================
CONFIGURATION
================================================================================

Fuzzy search is controlled by the database configuration:
- Table: app_config
- Key: Unison_Fuzzy_Default
- Value: "true" (enabled) or "false" (disabled)

To enable/disable:
UPDATE app_config SET definition = 'true' WHERE config_key = 'Unison_Fuzzy_Default';

No code changes needed - ConfigurationService reads this flag automatically.

================================================================================
PERFORMANCE CONSIDERATIONS
================================================================================

1. Pattern Generation:
   - Limited to 5 patterns per query (MAX_PATTERNS constant)
   - Transpositions limited to queries ≤15 chars (MAX_TRANSPOSITION_LENGTH)
   
2. SQL Performance:
   - Each fuzzy pattern adds one LIKE condition
   - Database can use indexes on columns where available
   - OR clauses combined efficiently
   
3. Frontend Performance:
   - Fast path for exact matches (no fuzzy processing)
   - Operates on already-loaded data (client-side filtering)
   - Levenshtein algorithm optimized with early termination
