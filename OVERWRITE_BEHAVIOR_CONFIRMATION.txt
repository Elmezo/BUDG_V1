================================================================================
                    تأكيد سلوك Overwrite في Dataset Values
================================================================================

تاريخ الإنشاء: 2025
الغرض: توثيق وتأكيد سلوك Overwrite لضمان التوافق مع Axon

================================================================================
1. سلوك Overwrite - نظرة عامة
================================================================================

عند اختيار "overwrite" كـ upload_type:
- يتم حذف جميع القيم القديمة (values_entry)
- يتم حذف جميع مراجع الرفع القديمة (values_entry_ref)
- يتم إنشاء entry_ref جديد
- يتم إدراج القيم الجديدة
- يتم تسجيل عمليتي audit: DELETE ثم INSERT

================================================================================
2. ما يتم تأثيره (Affected)
================================================================================

2.1 values_entry
----------------
✅ يتم حذف جميع الصفوف المرتبطة بالـ datastore
✅ يتم حذفها من جميع entry_refs القديمة
✅ يتم إدراج صفوف جديدة فقط

الكود:
------
if ("overwrite".equalsIgnoreCase(uploadType)) {
    // Delete all entries for this datastore
    String deleteEntries = "DELETE FROM values_entry WHERE entry_ref_id IN (
        SELECT id FROM values_entry_ref WHERE datastore_id = ?
    )";
    
    // Delete all entry refs for this datastore
    String deleteRefs = "DELETE FROM values_entry_ref WHERE datastore_id = ?";
}

2.2 values_entry_ref
--------------------
✅ يتم حذف جميع entry_refs المرتبطة بالـ datastore
✅ يتم إنشاء entry_ref جديد بنوع "OVERWRITE"

2.3 values_audit
----------------
✅ يتم إدراج سجل DELETE: "Overwrite triggered"
✅ يتم إدراج سجل INSERT: "Uploaded [N] rows via overwrite"

الكود:
------
insertAudit(conn, datasetId, "DELETE", userId, "Overwrite triggered");
// ... delete operations ...
insertAudit(conn, datasetId, "INSERT", userId, "Uploaded " + rowCount + " rows via overwrite");

================================================================================
3. ما لا يتم تأثيره (NOT Affected)
================================================================================

3.1 values_datastore (Metadata)
--------------------------------
✅ البيانات الوصفية (metadata) لا تتأثر بعملية overwrite
✅ frequency, frequency_comments, availability, availability_comments, values_in_axon تبقى كما هي
✅ updated_at لا يتحدث إلا إذا تم تحديث metadata مباشرة

الكود:
------
// Metadata update happens separately, only if metadataJson is provided
if (metadataJson != null && !metadataJson.isEmpty()) {
    // Update metadata
    String updateSql = "UPDATE values_datastore SET ... WHERE id = ?";
}
// This is independent of file upload

3.2 values_field
----------------
✅ Fields لا يتم حذفها
✅ Fields تبقى كما هي (قد يتم إنشاء fields جديدة إذا كانت موجودة في الملف الجديد)

ملاحظة:
-------
- إذا كان الملف الجديد يحتوي على أعمدة جديدة، سيتم إنشاء fields جديدة
- Fields القديمة (التي لم تعد موجودة في الملف) تبقى في قاعدة البيانات
- هذا متوافق مع Axon: Fields تعتمد على Structure (Attributes)

3.3 values_rule
---------------
✅ Rules لا تتأثر
✅ Rules المرتبطة بالـ fields تبقى كما هي

================================================================================
4. ترتيب العمليات في Overwrite
================================================================================

1. التحقق من الملف (validation)
2. إدراج audit entry: DELETE
3. حذف values_entry (جميع القيم القديمة)
4. حذف values_entry_ref (جميع المراجع القديمة)
5. إنشاء entry_ref جديد
6. إدراج values_entry (القيم الجديدة)
7. تحديث row_count في entry_ref
8. إدراج audit entry: INSERT

الكود:
------
if ("overwrite".equalsIgnoreCase(uploadType)) {
    // Step 1: Audit DELETE
    insertAudit(conn, datasetId, "DELETE", userId, "Overwrite triggered");
    
    // Step 2: Delete entries
    String deleteEntries = "DELETE FROM values_entry WHERE entry_ref_id IN (
        SELECT id FROM values_entry_ref WHERE datastore_id = ?
    )";
    
    // Step 3: Delete entry refs
    String deleteRefs = "DELETE FROM values_entry_ref WHERE datastore_id = ?";
    
    // Step 4: Create new entry_ref (happens later in code)
    // Step 5: Insert new entries (happens later in code)
    // Step 6: Audit INSERT (happens at end)
}

================================================================================
5. التوافق مع Axon
================================================================================

Axon Behavior:
--------------
- Overwrite = DELETE + INSERT منطقياً
- Metadata لا يتأثر
- Audit يتبع العملية

التنفيذ الحالي:
---------------
✅ متوافق تماماً مع Axon
✅ DELETE قبل INSERT
✅ Metadata محمي
✅ Audit صحيح

================================================================================
6. أمثلة عملية
================================================================================

مثال 1: Overwrite بدون تحديث Metadata
--------------------------------------
الحالة الأولية:
- frequency = "Daily"
- availability = "Via Application UI"
- 5 صفوف موجودة

العملية:
- رفع ملف جديد بـ overwrite (10 صفوف)
- عدم تحديث metadata

النتيجة:
- frequency = "Daily" (لم يتغير)
- availability = "Via Application UI" (لم يتغير)
- 10 صفوف جديدة فقط (القديمة محذوفة)
- Audit: DELETE ثم INSERT

مثال 2: Overwrite مع تحديث Metadata
-------------------------------------
الحالة الأولية:
- frequency = "Daily"
- 5 صفوف موجودة

العملية:
- رفع ملف جديد بـ overwrite (10 صفوف)
- تحديث metadata: frequency = "Weekly"

النتيجة:
- frequency = "Weekly" (تم التحديث)
- 10 صفوف جديدة فقط (القديمة محذوفة)
- Audit: DELETE ثم INSERT

ملاحظة: تحديث metadata منفصل عن overwrite، لكن يمكن أن يحدث في نفس الطلب.

================================================================================
7. التحقق من السلوك
================================================================================

SQL للتحقق:
-----------
-- قبل overwrite
SELECT frequency, availability FROM values_datastore WHERE dataset_id = ?;
SELECT COUNT(*) FROM values_entry_ref WHERE datastore_id = ?;
SELECT COUNT(*) FROM values_entry WHERE entry_ref_id IN (
    SELECT id FROM values_entry_ref WHERE datastore_id = ?
);

-- بعد overwrite
SELECT frequency, availability FROM values_datastore WHERE dataset_id = ?;
-- يجب أن تكون نفس القيم (ما لم يتم تحديثها)

SELECT COUNT(*) FROM values_entry_ref WHERE datastore_id = ?;
-- يجب أن يكون 1 (entry_ref الجديد فقط)

SELECT COUNT(*) FROM values_entry WHERE entry_ref_id IN (
    SELECT id FROM values_entry_ref WHERE datastore_id = ?
);
-- يجب أن يكون عدد الصفوف الجديدة فقط

================================================================================
8. الخلاصة
================================================================================

✅ Overwrite يؤثر فقط على:
   - values_entry (حذف القديم، إدراج الجديد)
   - values_entry_ref (حذف القديم، إنشاء الجديد)
   - values_audit (إدراج DELETE و INSERT)

✅ Overwrite لا يؤثر على:
   - values_datastore metadata (يبقى كما هو)
   - values_field (يبقى كما هو)
   - values_rule (يبقى كما هو)

✅ هذا متوافق تماماً مع سلوك Axon
