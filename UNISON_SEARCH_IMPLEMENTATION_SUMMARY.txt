================================================================================
TECHNICAL DETAILS
================================================================================

Backend Implementation:
----------------------
- **Search Orchestration**: `UnisonSearchService` executes seed searches, then uses `GraphTraversalService` to expand results based on relationships (`maxDepth`).
- **Query Generation**: `QueryBuilder` dynamically constructs SQL. It identifies searchable columns per module and applies fuzzy patterns if enabled.
- **Fuzzy Logic**:
  *   Generates up to 5 variations per term (Original, Phonetic, Transposed, Wildcard).
  *   SQL: `(col LIKE ? OR col LIKE ? ...)`
- **Graph Traversal**: Finds related objects by querying relationship tables/FKs. Used for "Find Data Sets related to this Person".

Frontend Implementation:
-----------------------
- **Modular Architecture**: Separate files for Init, API, UI, and logic, loaded via `loading-manager.js` (implied).
- **Interactive Dashboards**: `search-dashboard.js` computes client-side statistics (Counts by Lifecycle, Status, etc.) from fetched data and renders Chart.js (or similar) visualizations.
- **State Management**: URL parameters (`q`, `searchId`, `module`) drive the application state, allowing shareable links.

================================================================================
CONFIGURATION
================================================================================

Unison Search behavior is controlled via `app_config` table:

- **Unison_Fuzzy_Default**: "true" / "false"
  - Controls whether fuzzy pattern generation is applied by default.

To toggle via SQL:
UPDATE app_config SET definition = 'false' WHERE config_key = 'Unison_Fuzzy_Default';

================================================================================
PERFORMANCE CONSIDERATIONS
================================================================================

1. **Pattern Limits**: `FuzzySearchUtil` limits generated patterns to 5 to prevent SQL query explosion.
2. **Graph Depth**: `maxDepth` parameter in `UnisonSearchService` limits recursion depth to prevent infinite loops or massive joins. default is usually 2.
3. **Lazy Loading**: Dashboards and Tables are rendered after data fetch.
4. **Client-Side Filtering**: Dashboard interactions often filter the already-loaded dataset in memory for sub-second response.
